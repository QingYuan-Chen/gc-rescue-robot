# MaixCAM 视觉程序

当前包含一个有效的数据采集程序和一个旧工程参考程序。

## 连拍采集程序 `capture_burst.py`

用途：在 MaixCAM Pro 上采集数据集图片。短按板载 USER 键后，程序在 2 秒时间窗内连续拍摄 5 张照片（默认间隔 400 ms，第 5 张约在触发后 1.6 s 完成），每次触发生成独立子目录：

```text
/root/data/burst_capture/cap_YYYYmmdd_HHMMSS/
  01.jpg ... 05.jpg
  meta.txt        # 触发时间、每张实际时刻、成功率
```

运行方式：把 `capture_burst.py` 传到设备（MaixVision 直接打开运行，或在终端执行 `python capture_burst.py`）。

- 短按 USER 键触发一组；拍摄过程中再次按下会被忽略。
- 创建 `key.Key` 对象会取消 MaixPy 默认的“USER 键退出”行为，因此程序改为长按 3 秒退出，屏幕上有英文提示。
- 每拍完一组调用 `os.sync()` 主动刷盘，降低断电丢图风险。
- 分辨率、张数、间隔、保存目录和触发键都在文件顶部常量中调整；默认 640×480、30 fps。
- 状态：仅完成静态检查，未在 MaixCAM Pro 上实测。按键映射（默认 `KEY_OK`）、实际拍摄间隔、保存耗时和存储路径需要在设备上确认；日志会打印未配置按键的 id，便于按实际映射修正 `TRIGGER_KEYS`。

## 旧工程参考程序 `main.py`

此目录的 `main.py` 来自旧工程，尚未迁移为 TB67H450 项目的有效视觉程序。当前 STM32 构建和任务入口没有调用或接收它的协议。

保留它是为了后续重建视觉功能时追溯图像处理逻辑，不表示其中的接口和参数仍适用：

- 发送格式是 `0x55 0xAA` 加 12 字节大端载荷，接收格式是相同帧头加单字节模式号；当前 UART5 采用文本调试协议，两者不互通。
- `/dev/ttyS0`、A16/A17、模型绝对路径和类别顺序均为旧设备假设，未在当前硬件重新确认。
- 旧的抓球、基地和模式状态机还没有对应的新版 STM32 任务接口。

本轮只补充历史边界说明，不运行此脚本、不迁移旧协议或动作。视觉接入阶段应先确认设备、模型与新版通信契约，再按当前[工程规范](../../docs/工程规范.md)重构；当前有效入口见[项目说明](../../README.md)。
