# 车轮 PI 控制设计

日期：2026-10-15。状态：源码与离线验证完成，尚未烧录、整定或完成硬件验收。

用户已确认由原 PID 等效移植转入当前车体的 PI 重构。后续调参统一使用 **C 左轮，由用户亲自操作**；具体调试方案由用户另行提供。本次不新增自动调参、串口运动脚本、上电运动任务或在线改参协议。

原算法、参数及 2026-10-14 的试验结果分别保存在 [PID 迁移对照](PID迁移对照.md)、[阶段 4 历史验收](validation/2026-10-14-stage4-speed.md)和提交 `57ab4f7`。新实现不再维持与原算法逐周期等效，不能把旧测试结论用于新固件。

## 1. 保留与替换

保留 10 ms 固定周期、C 左/D 右映射及方向、每轮独立状态、唯一电机输出入口、停止优先、到期停车、模式切换和单轮停用规则。零速度仍是闭环给定，显式停车才退出控制并清状态。

当前构建内的增量式 PID、未接入业务的位置式 PID、原 CCR 参数和 CCR 到占空比适配已被替换为一套 PI。`firmware/stm32/gc_rescue/` 中仍供后续模块提取的旧参考链不参与构建，同级原工程不改动。

暂不加入微分、误差死区、速度滤波、摩擦前馈或最小启动 PWM。上述机制需要根据用户后续测试判断，不能以扩大死区掩盖低速误差。没有自动停稳判据，零速闭环也不等同于位置锁定。

## 2. 单位与默认参数

| 参数或量 | 约定 |
| --- | --- |
| 目标、反馈、误差 | counts/10 ms，前进为正；目标允许小数，反馈为每周期编码器整数增量 |
| P 项、I 项、PI 请求及实际输出 | 有符号占空比千分比；250 表示幅值 25% |
| Kp | 千分比/(counts/10 ms) |
| Ki | 千分比/[(counts/10 ms)·s]，计算时显式乘 `dt_s=0.01` |
| `tracking_gain_per_s` | 回算增益，单位 1/s，等于回算时间常数的倒数 |
| 有效速度环输出范围 | ±250‰，唯一业务定义在 `App/config/wheel_config.h` |

每轮参数在 [wheel_pid_config.h](../firmware/stm32/App/config/wheel_pid_config.h) 的 `wheel_pid_defaults` 中分别配置，初始化时复制到对应实例。左右轮默认 `Kp=0、Ki=0`，因此当前固件的速度命令即使被接受，也不会产生驱动输出；开环命令仍按原有独立规则工作。

回算增益暂取 `10/s`，即时间常数 0.1 s、每周期回算系数 0.1；这是实现初值，不是已整定值。参数须为有限非负值；启用积分时回算增益为正，且满足 `0 < dt_s × tracking_gain_per_s <= 1`。当前参数为编译期常量，未开放来自串口的参数写入；后续若加入在线调参，再由该入口验证参数并交接到控制任务。

旧参数 `1600/180` 使用 CCR 单位及隐含周期，不能直接填入新接口。旧值与来源仅供追溯，当前不自动换算或复制成默认增益。右轮保持独立待整定状态，不随左轮参数修改。

## 3. 单周期计算与回算

PI 使用显式积分项的位置式写法，控制目标仍是轮速。每个正常控制周期依次执行：

```text
e[k]       = target[k] - measured[k]
P[k]       = Kp × e[k]
u_raw[k]   = P[k] + I[k]
u_bound[k] = clamp(u_raw[k], -250, +250)
u_request  = 向零取整(u_bound[k])
u_applied  = 应用换向规则后的实际输出

发生限幅或换向约束时：
I[k+1] = I[k] + 0.01 × (Ki × e[k] + Kaw × (u_applied - u_raw[k]))

没有上述约束时：
I[k+1] = I[k] + 0.01 × Ki × e[k]
```

`Kaw` 为 `tracking_gain_per_s`。回算使用同周期最终采用的输出，包括换向零输出，修正留给下一周期的积分状态，不直接把积分赋值为 PWM。当前输出使用的是 `I[k]`，更新后的 `I[k+1]` 单独保存，状态查询可同时检查二者。首次从清零状态启动时积分贡献为零，本周期误差从下一周期起贡献积分。

普通浮点到整数 PWM 的取整不触发回算，否则不足一个 PWM 计数的小积分可能长期被抵消，形成隐性死区。输出浮点数先限幅再转整数，避免先转整数而丢失实际限幅信息。底层电机接口仍保留 ±1000‰ 的物理范围防护，它不会进一步改变当前 ±250‰ 的合法闭环输出。

`Ki=0` 时积分及回算均关闭，积分状态归零，只输出 P 项，避免纯 P 调试时回算产生隐藏积分。新算法不再使用原 ±1599 CCR 的积分抑制边界，也不额外叠加一个与实际驱动范围无关的积分限幅。

## 4. 生命周期和模块边界

| 情况 | 行为 |
| --- | --- |
| 启动、显式停车、命令到期或周期故障 | 输出归零，清 PI 当前项及下一周期积分状态 |
| 同一速度模式更新目标或续期 | 保留状态，包括目标经过正、零、负值 |
| 开环与闭环互切 | 清状态，保留一个完整 10 ms 零输出周期；该周期不计算 PI、不积分 |
| 单轮启用状态改变 | 只清被停用或新启用的实例，连续启用侧保留历史 |
| 输出正负直接翻转 | 对应轮子插入 10 ms 零输出；继续采样、计算，并回算到该次实际零输出 |

- `control/pid.c`：纯 PI 计算与回算；不依赖 HAL、FreeRTOS、电机引脚或车轮编号。
- `control/wheel_pid.c`：复制每轮参数，将 10 ms 周期和轮速单位接入 PI，提供状态快照接口。
- `control/wheel_drive.c`：唯一周期编排者，管理模式、期限、有效输出上限与换向，并把采用结果交回 PI。
- `bsp/motor.c`：唯一 PWM 和方向 GPIO 写入入口。
- `debug/wheel_status.c`：只读取快照并格式化，不参与控制计算。

`wheel_drive_init()` 由装配层传入左右参数。主机测试可传入独立测试参数，固件始终使用配置文件中的默认值，没有条件编译的测试算法或第二条电机控制路径。

## 5. 观测与后续调试边界

`wheel status` 增加 `controller=pi output_unit=permille` 标识，输出如下逐周期快照：

| 字段 | 含义 |
| --- | --- |
| `p_left/right` | 当前比例项 P[k] |
| `i_left/right` | 本次输出使用的积分项 I[k] |
| `i_next_left/right` | 正常积分及约束回算后，留给下一周期的 I[k+1] |
| `pi_left/right` | 未限幅输出 P[k]+I[k] |
| `request_left/right` | 已施加 ±250‰ 限幅和取整、尚未施加换向间隔的请求 |
| `duty_left/right` | 实际采用的输出 |
| `limited_left/right`、`reverse_left/right` | 幅值限制、换向零输出标志 |

其余目标、反馈、累计计数、周期与停车字段保留，详见 [UART5 协议](UART5调试串口.md)。删除旧 `pid_left/right` CCR 字段及其解释，检查工具只接受当前 PI 协议，不混用历史数值。

控制状态每 10 ms 更新；现有 UART 查询仍是即时快照，不是连续采样记录，也不能保证每周期都被电脑收到。连续记录的缓存、导出方式、在线改参命令及具体左轮测试流程按用户后续调试方案接入，本次不预设这些协议、不进行硬件调参。

## 6. 验证与剩余工作

纯算法测试覆盖显式时间尺度、Ki=0、零目标保留积分、正负饱和恢复、换向回算和取整不吞掉小积分；控制层测试继续覆盖模式、停止、到期、独立状态、限幅、周期故障及协议，另检查实际固件零增益默认值。

测试参数只用于离线固定输入，不是推荐电机参数。结果见 [PI 重构验证记录](validation/2026-10-15-wheel-pi-refactor.md)。离线通过不能证明实际电机低速、零速或负载下稳定。后续由用户在左轮开展调参，再按确认的范围进行右轮与双轮验证；速度环仍未完成阶段 4 验收。
