# 车轮速度测量设计

日期：2026-10-16。状态：**方案待审核、固件待实施**。本次完成源码核查后的方案比较与独立数学模型验证，未修改 STM32 源码、连接硬件、烧录、转轮、调参或提交 Git。

推荐以 **50 ms 滑动计数窗口，每 10 ms 更新一次**作为首个上板候选。编码器继续累计位置，新增独立速度估计模块；PI 反馈、误差和 VOFA 共用同周期的估计值，原始计数保留用于诊断与里程计。先验证测量，再由用户在 C 左轮整定 PI。

## 1. 当前问题与设计目标

已核查的现有路径是：16 位计数器差分 → 每 10 ms 整数增量 → PI 和 VOFA。目标、反馈和误差统一为 counts/10 ms，没有发现这条路径漏除采样时间或误差减法错误；但它把单周期整数增量直接作为速度，缺少独立估计层。详见[速度与误差专项核查](validation/2026-10-16-speed-measurement-audit.md)。

例如，真实恒速 2.5 counts/10 ms 可能产生 `2,3,2,3…` 的原始反馈。Kp=30、目标=5 时，即使机械速度完全恒定，纯 P 输出也会在 60～90‰ 之间变化。转成 float、增加显示小数位或改为 counts/s 都不能增加编码器信息。

当前证据只能确认量化可以独立造成跳变，不能断言现场 2～4 的全部变化都来自量化。真实机械波动、编码器信号和任务采样时序仍需通过固定输出采集区分。纯 P 的目标静差也不能靠测速平滑消除。

本方案的目标是获得**单位明确、延迟可解释、与控制一致的轮速平均估计**。不以曲线绝对光滑作为成功标准，不用死区、按目标裁剪或仅处理 VOFA 显示掩盖问题。

## 2. 数据与时间基础

| 项目 | 约定 |
| --- | --- |
| 物理映射 | C 左轮，TIM4；D 右轮，TIM8；沿用已验收的编码器符号，前进为正 |
| 原始位置 | 16 位自由运行计数器，不读后清零；回绕差分仍由 `bsp/encoder.c` 处理 |
| 原始增量 | `delta_counts`，本次采样与上次采样之间的有符号整数差 |
| 累计位置 | `int64_t total_counts`，累加原始增量；不由滤波速度积分重建 |
| 控制与采集周期 | 10 ms，继续使用唯一车轮任务 |
| 时间来源 | 紧邻计数器读取的 MCU 采样时刻，沿用现有 1 ms RTOS tick；不使用串口发送或电脑接收时间 |
| 对外速度、目标、误差 | counts/10 ms；速度估计使用 float，单位不变 |
| VOFA | 保留八通道和每 10 ms 一帧的正常采样节奏 |

每轮一圈计数尚未标定，因此这一阶段不编造 RPM 或 m/s。后续标定出输出轮每转计数 `C_rev` 与轮周长 `L_m` 后，可在物理单位接口换算：`rpm = 6000 × speed / C_rev`，`m/s = 100 × speed × L_m / C_rev`；不要重复乘编码器倍频或减速比。

## 3. 推荐算法

### 3.1 最近五个有效区间求平均

设本次累计位置为 `P[k]`，对应 MCU 时间为 `t[k]`，保存最近六个位置与时间点，覆盖五个 10 ms 区间：

```text
window_counts = P[k] - P[k-5]                  // 先做有符号整数差
window_ms     = uint32(t[k] - t[k-5])          // 无符号模差处理时间回绕
speed[k]      = float(window_counts) × 10.0 / window_ms
error[k]      = target[k] - speed[k]
```

正常周期下 `window_ms=50`，等价于最近五个原始增量之和除以 5。窗口每个控制周期向前移动一格，**不会改成每 50 ms 才更新一次控制器**。使用实际记录的窗口跨度，禁止把五次采样无条件视为 50 ms；异常间隔的处理见第 5 节。

累计位置先在 `int64_t` 域做差，再转 float。不要先把两个长期累计位置转成 float 再相减，否则会在累计值增大后损失小增量。

这一层只做一次滑窗平均，不再串联低通、中值滤波、死区或速度限幅。统计窗口长度集中配置为五个区间，不开放 VOFA 在线修改；更改窗口会改变反馈动态，需要重新验证并评估 PI 参数。

### 3.2 精度与代价

| 指标 | 50 ms 方案 |
| --- | --- |
| 正常输出更新周期 | 10 ms |
| 输出量化步长 | 0.2 counts/10 ms；编码器物理分辨率不变 |
| 对理想窗口平均速度的计数量化误差 | 幅值小于 0.2 counts/10 ms；前提是无漏脉冲、方向正确、时间准确 |
| 相对原 10 ms 增量的低频附加群延迟 | 20 ms，即五点平均的 `(5-1)/2` 个周期 |
| 相对连续真实速度的窗口中心 | 约在当前采样时刻之前 25 ms；不能把 20 ms 和 25 ms 混为一谈 |
| 旧计数完全退出窗口 | 最后一个产生位移的区间之后，连续五个零增量区间使结果精确为零 |

正向恒速 2.5 的估计仍可能在 2.4、2.6 之间变化；恒速 2.37 可能在 2.2、2.4 之间变化。剩余台阶是可解释的测量分辨率，不应继续叠加滤波只为得到直线。

50 ms 是初始工程选择，不是已经证明的闭环最优窗口。其依据是把当前量化步长从 1 收窄到 0.2，并把额外延迟控制在 20 ms；真实负载下的响应与稳定性必须上板确认。

## 4. 方案比较与离线依据

### 4.1 恒速比较

采用理想累计位置模型 `P[k] = floor(phase + k × speed)`，再做相邻差分生成整数编码器输入。比较原 10 ms 增量、20/40/50/100 ms 滑窗和一阶低通 `y[k]=y[k-1]+(d[k]-y[k-1])/3`。

速度幅值为 `0.1、0.25、0.5、1.1、2.0、2.13、2.37、2.5、3.2、3.73、5.13、7.61、9.7、10.0`，正反方向各测一次；初相位取 `0/16…15/16`，共 **448 组条件**。每组生成 1200 个区间，舍去前 200 个，统计随后 1000 个。所有方案使用相同输入；整数边界加入 `1e-10` 数值容差，避免浮点生成的舍入误差制造伪脉冲。

下表统计其中 `2≤|speed|≤10` 的 320 组，覆盖当前几个计数量级的观测范围。均方根误差先汇总全部有效采样再开方，单位均为 counts/10 ms；附加延迟是相对原 10 ms 增量的低频理论值。

| 方法 | 综合均方根误差 | 最大稳态峰峰值 | 附加延迟 | 取舍 |
| --- | --- | --- | --- | --- |
| 原 10 ms 增量 | 0.3891 | 1.000 | 0 ms | 响应快，当前量化扰动明显 |
| 20 ms 滑窗 | 0.1922 | 0.500 | 5 ms | 仍存在较大的半计数台阶 |
| 40 ms 滑窗 | 0.0932 | 0.250 | 15 ms | 可作后续响应更快的候选 |
| **50 ms 滑窗** | **0.0737** | **0.200** | **20 ms** | 本次推荐的初始折中 |
| 100 ms 滑窗 | 0.0305 | 0.100 | 45 ms | 恒速更细，动态滞后明显增加 |
| 一阶低通，α=1/3 | 0.0979 | 0.333 | 20 ms | 相近低频延迟下残余纹波更大，停车有衰减尾巴 |

本组稳态统计中，各方法均值与输入一致，差别仅为浮点舍入量级；这是所选有限样本的结果，不能推广成对所有实际输入无偏。窗口恰好覆盖某个脉冲重复周期时会得到直线，例如 50 ms 对 3.2、40 ms 对 2.5；不能拿一个这样的例子证明某窗口普遍最优。

### 4.2 动态比较

合成速度在 300 ms 的采样边界发生变化；下一次输出在 310 ms，表内时间从 300 ms 起算。阶跃只是辨识估计器延迟，不代表真实电机可以瞬间变速。

| 方法 | 2→6 达到变化量 90% | +4→−4 首次报告负值 | 4→0 后首次精确为零 |
| --- | --- | --- | --- |
| 原 10 ms 增量 | 10 ms | 10 ms | 10 ms |
| 20 ms 滑窗 | 20 ms | 20 ms | 20 ms |
| 40 ms 滑窗 | 40 ms | 30 ms | 40 ms |
| **50 ms 滑窗** | **50 ms** | **30 ms** | **50 ms** |
| 100 ms 滑窗 | 90 ms | 60 ms | 100 ms |
| 一阶低通，α=1/3 | 60 ms | 20 ms | 700 ms 观测内仍有衰减尾巴 |

另外用 300～800 ms 内从 1 增至 9 的连续线性斜坡，先积分生成位置，再量化，初相位为 0.37。斜率为每秒增加 16 counts/10 ms；在 410～790 ms 的公共区间统计，50 ms 估计相对采样端点真实速度的平均偏差约为 −0.40，100 ms 约为 −0.80。这主要是窗口延迟，不应误判为新的比例换算错误。未来调参必须接受并检查这一动态代价。

### 4.3 本次验证的边界与留档

独立设计模型还检查了窗口预热、`uint32_t` 时间回绕、大累计位置先作整数差、异常采样后重建窗口、反向计数和停车后旧计数逐步退出。模型通过这些检查；正式 C 模块尚未编写，不能将结果记作固件模块通过。

本次使用 Python 3.13.9、NumPy 2.3.5 和 Matplotlib 3.10.6。完整结果位于本地忽略目录 `build/vofa/speed-measurement-design/`：`results.json`、`constant-speed.csv`、`dynamic-traces.csv` 和 `speed-measurement-comparison.png`。比较程序通过标准输入一次性运行，没有新增长期测试脚本或固件测试入口。

这些输入是合成编码器数据，输出不会反过来影响输入；**它们不是实车采样，也不是电机闭环仿真**。本节给出模型、输入与统计口径作为可追溯记录，不证明电机控制稳定性。

## 5. 初始化、异常与运动状态

测速状态与控制模式分开管理。只要采样有效，停车、开环、闭环都持续更新位置和测速窗口。

| 场景 | 测速行为 | 控制与上报行为 |
| --- | --- | --- |
| 上电第一次读取 | 建立位置与时间基线；基线之前的增量不计入有时长的速度估计 | `speed_valid=false`，保持零输出，不发布伪造的零速度帧 |
| 随后前四个正常区间 | 累积真实样本，不用零补齐五点窗口 | 闭环启动返回未就绪；状态查询可见有效性与已覆盖时长 |
| 五个正常区间齐备 | 第 50 ms 起提供完整窗口估计，`speed_valid=true` | 允许按现有显式命令启动；VOFA 正常采集 |
| 修改目标或 Kp/Ki | 保留窗口，物理测量不随控制参数重置 | 保留已约定的 PI 在线更新规则 |
| 开环/闭环切换、单轮启停 | 两轮各自窗口持续更新，不清空仍在转动的反馈 | 沿用 PI 清状态及模式过渡规则 |
| 目标过零、正负反转 | 只使用编码器有符号位移；窗口跨越反转时自然包含正负计数 | 不按目标方向修改速度符号，不提前把窗口清零 |
| 显式停车或开环到期 | 撤输出后继续观察惯性运动，随实际计数更新 | 清 PI，不清测速；停车命令不等待窗口归零 |
| 窗口内没有净位移 | 平均速度为零，仍可查询原始增量 | 不能据此宣布机械停稳；前后运动可能相互抵消 |
| 调度报错、间隔不是 10 ms 或时间重复 | 当前估计失效，以本次位置和时间重新建立基线 | 保留现有周期故障锁定停车；不得用旧速度继续 PI |
| 故障后又得到五个正常区间 | 重新提供有效速度，用于诊断惯性与手动转轮 | 周期故障仍锁定，不自动恢复运动 |
| `vofa on/off` 或无线丢帧 | 不重置窗口，不改变控制反馈 | 不影响控制任务；按原采样时间识别上报缺口 |

初始预热或异常重建期间，VOFA 跳过无效测速帧；时间轴保留缺口，`wheel status` 提供有效性，不用 `0`、上一帧或插值冒充有效测量。正常运行时开启 VOFA 不会再等待 50 ms，因为测量一直在后台进行。

现有毫秒时间戳只能识别相应尺度的调度异常，不能证明两次硬件读取精确相隔 10000 μs。实现时将取时与计数器读取保持紧邻、避免夹入通信和耗时处理；若固定输出采集仍指向亚毫秒抖动，再增加高分辨率采样时序观测定位根因，不把此问题归结为 PI 参数或继续扩大滤波窗口。

## 6. 模块划分与接入清单

```text
编码器硬件累计计数
  → bsp/encoder：回绕差分、方向统一
  → control/wheel_drive：累计位置、周期检查
  → control/wheel_speed：50 ms 平均速度及有效性
  → 同周期速度/目标/误差快照
      → wheel_pid / pid：PI 计算 → 唯一电机输出路径
      → vofa_stream：八通道格式化与发送
```

| 位置 | 计划修改与职责 |
| --- | --- |
| `App/bsp/encoder.c/.h` | 保留原始计数采集接口与符号；不混入滑窗、PI、串口代码 |
| `App/control/wheel_speed.c/.h`，新增 | 每轮独立实例；输入累计位置、时间戳及采样连续性，输出估计速度、有效性和窗口跨度；保存六个采样点；不依赖 HAL、FreeRTOS、控制目标或电机输出 |
| `App/config/wheel_speed_config.h`，新增 | 集中定义五个区间的窗口；10 ms 周期引用既有唯一配置，不复制常数 |
| `App/control/wheel_drive.c/.h` | 在采集后、计算 PI 前更新估计器；快照保留 raw/delta/total，增加速度、速度误差、有效性及窗口跨度；负责失效时禁止控制 |
| `App/control/wheel_pid.c/.h` | 测量参数由 `int32_t measured_delta_counts` 改为单位明确的浮点速度；目标参数命名同步体现速度；10 ms PI 积分周期不变 |
| `App/control/pid.c/.h` | 通用 PI 算法、限幅回算职责保持原设计，不在内部滤波测速 |
| `App/debug/vofa_stream.c` | 采集同周期速度与误差快照，按三位小数发送；删除从原始增量生成速度/误差的旧路径 |
| `App/debug/wheel_status.c` | 保留原始量，增加估计值、有效性和窗口跨度；仅查询与格式化 |
| 构建、主机测试、说明文档 | 注册新源文件，替换原始增量直通反馈的预期，补充第 9 节测试，同批清理失效注释与接口 |

估计器的状态由调用方分配并通过公开接口维护，不动态分配内存、不新增任务、不增加第二个 PWM 写入者。时间连续性与停车策略由 `wheel_drive` 判断；传入估计器的是本周期采样是否连续，不是已经锁存的周期故障位，因此故障停车后仍能恢复诊断测速。估计模块不自行解除故障或请求运动。

`speed_counts_per_10ms` 与 `error_counts_per_10ms` 是计划中的字段含义；`delta_counts` 继续明确表示原始增量，不能只改字段值却沿用原始增量的名称。控制层对目标做一次单位转换，速度误差为 `target-speed`；有效闭环周期要求 PI 的误差与快照一致。

未来里程计直接使用原始累计位置或增量，不积分滤波速度，否则会把速度窗口的迟滞带入位移估计。

## 7. VOFA 显示与参数

八个通道顺序不变，实施后只替换速度与误差的数据来源：

| 通道 | 实施后的含义 |
| --- | --- |
| 0 | 本周期 MCU 采样时间，不能为了对齐曲线向前挪 25 ms |
| 1 | 当前生效目标，counts/10 ms |
| 2 | 50 ms 窗口速度估计，counts/10 ms，显示三位小数 |
| 3 | 同周期目标减同一速度估计，counts/10 ms |
| 4 | 同周期最终采用的占空比，‰ |
| 5、6、7 | 实际生效 Kp、Ki、Kd；Kd 继续固定为零 |

界面建议把通道 2 命名为“反馈速度（50 ms 窗口）”，避免将它当作无延迟的瞬时真值。三位小数用于一致的参数显示，不代表分辨率达到 0.001。

停车与开环期间仍可显示 `目标-估计速度`，但它不表示 PI 正在控制；不能从已经清零的 PI 内部状态直接取此时的显示误差。模式、原始增量/累计计数和测量有效性继续通过 `wheel status` 查询，不扩充用户固定八通道。

固件实施时 PI 与 VOFA 必须一起切换到估计反馈。不能只让波形变平滑，而让控制器继续受整数增量跳变驱动。左右 Kp/Ki 上电仍为零，右轮不复制左轮参数；已试过的增益因反馈动态改变需要重新评估。

## 8. 低速范围与后续升级条件

目标允许输入 0.1，不等于已经具备 0.1 counts/10 ms 的稳定测速和闭环能力。理想恒速 0.1 时约 100 ms 才产生一个计数，50 ms 窗口输出仍会在 0 与 0.2 之间变化。

把窗口改成 100 ms，恰好可以让这个理想输入得到 0.1，但不能因此认定超低速问题已解决：其他速度、脉冲不均匀、机械爬行和更慢速度仍有各自的分辨率与延迟限制。若需要把量化步长降到 0.01，单纯延长计数窗口需要约 1000 ms，明显不适合直接照搬为当前速度环反馈。

因此本阶段先在当前几个 counts/10 ms 的观测量级验证 50 ms 方案，再实测低速能力边界，不预设未经验证的最小可控速度。

若后续比赛动作确实要求更慢的持续轮速，再单独评估基于编码器边沿时间戳的 T 法，或结合计数与测时的 M/T 法。此时必须先核实定时器、输入捕获或中断资源及时间精度，并设计方向反转、停转后旧周期失效和无边沿时的结果更新。**现有 10 ms 轮询读数没有真实边沿时间，不能把检测到计数变化的任务时刻当成边沿时刻。** 本轮不加入无法验证的自动测速模式切换，也不假定这些资源已可直接使用。

## 9. 实施与验收顺序

### 第一步：审核设计，完成正式模块与离线测试

本次只交付设计。实施时测试正式 C 模块，而非继续仅测 Python 模型：

- 整数、非整数、正反向和稀疏脉冲输入；完整窗口估计逐周期等于参考式，浮点误差在 `1e-5 counts/10 ms` 内。
- 10 ms 原始增量总和与累计位置一致；16 位计数回绕后无伪速度；大累计位置不丢失小增量。
- 窗口未满不补零冒充有效数据；时间回绕、异常区间和五个有效区间恢复符合第 5 节。
- 目标改变、模式切换、停车和单轮停用不清测速历史；换向结果由计数决定；左右状态互不污染。
- PI、快照和 VOFA 使用同周期同一反馈，显示舍入误差不超过三位小数的精度；速度改为小数后重新检查帧长、发送缓冲与 100 Hz 串口吞吐；周期异常立即撤输出且不自动恢复。
- 在原主机测试入口补充必要测试，完成 Debug/Release 构建；不把一次性测试代码烧入固件。

### 第二步：经用户确认烧录，先验收测速

固件构建通过后仍需用户确认烧录。运动采集由用户在架空的 **C 左轮**操作，先使用固定开环输出，右轮保持停用；保持既有限时开环约束，不由助手自动发送运动指令。

记录输入、供电和接线条件，分别采集可持续转动的几个输出档位、正反转及撤输出后的惯性过程。均匀转速段重点检查估计均值、原始计数、实际时间和是否存在无法由量化解释的跳变。原始计数可由已有状态查询获取；若需要连续原始样本，专项诊断只使用临时主机采集或调试器，不长期扩充八通道协议。

硬件验收不能要求“估计速度等于目标”，因为此步是固定输出。应核对样本能否按公式复算、累计位移是否一致、方向是否正确及额外滞后是否符合预期；机械静止或人工标记轮转可提供独立交叉检查。有限状态快照不够定位时必须补采数据，不能把滤波后的平滑当成正确性的证据。

### 第三步：由用户重新整定 PI

测量通过后，用户按自己的调试方案整定左轮；检查加速、减速、零目标、反向和负载变化。50 ms 方案若使响应无法接受，应根据记录重新选择窗口或测速方式，不能只不断加大 Kp。随后再验证右轮和后续转向环。

测速估计、实际机械停稳判断和异常保护是不同职责。本次不引入未经实测的停稳阈值、自动脱困、摩擦补偿或任务成功判据。
