# 2026-10-12 UART5 无线调试串口验证

## 范围与基线

基于 `553a4bf422c8aae5cfd5880042475e37dc1bfade` 的阶段 1 稳定版本。用户要求在阶段 2 车轮重构前，将已连接的无线 DAPLink UART 配置为调试串口，并在测试通过后提交、推送。本次只接入 UART5，不启动电机、舵机、编码器或 PID。

## 构建与配置

- 工具链：CMake 3.28.1、Ninja、ARM GCC 13.3.1，STM32CubeCLT 1.20.0。
- `stm32-debug`、`stm32-release` 均构建通过，新 App 模块使用 `-Wall -Wextra -Werror`，无编译告警。
- `.ioc` 启用 UART5 初始化及优先级 7 的中断，移除 UART5 RX DMA；新增调试任务，基础周期任务优先级高于调试任务。
- CubeMX 副本再生成后，`main.c`、`freertos.c`、`usart.c`、`stm32h7xx_it.c/.h`、`dma.c`、`usart.h` 共 7 个文件的非注释内容一致。
- 副本导出仍有本机扩展包 PDSC 与 Makefile 的 `sysmem.c/syscalls.c` 重复绝对路径诊断，与阶段 1 相同；此次只确认相关 Core 内容再生成一致，未将完整 IDE 导出记为通过。

## 设备与烧录

- 电脑端：Horco CMSIS-DAP v2，VID:PID `FAED:4873`，序列号 `3FEE83BB`，虚拟串口 `COM5`。
- 目标：STM32H750，IDCODE `0x20036450`，Flash 128 KiB，UID 三字为 `0x0042001e / 0x33335115 / 0x39333631`。
- 接线：UART5 PB13 TX、PB12 RX、GND 连接无线收发器，115200、8N1、无流控；核心板供电，无需执行器供电。
- 使用 OpenOCD 0.12.0、100 kHz 无线 SWD，烧录前完整备份，写入后逐字节核对完整 128 KiB Flash（固件外的擦除区域也一致）。

## 无线串口实测

| 测试 | 输入 | 实测结果 |
| --- | --- | --- |
| 双向链路 | 连续 100 次 `ping` | 100 次均收到 `OK pong` |
| 命令边界 | CR、LF、CRLF、分段 `pi`/`ng`、退格 | 均正确响应，无重复执行 |
| 参数读写 | `get report_ms`、设置 `60000`/`100`/`0` | 写入和回读一致 |
| 非法参数 | 负数、99、60001、带字母、超大整数、多余参数、未知名称 | 均返回 `ERR`，原参数不变 |
| 残缺输入恢复 | 120 字节超长行、包含 NUL 的参数命令 | 丢弃整行，后续正常命令仍可用，原参数不变 |
| 自动上报 | `set report_ms 100`，接收 6 条状态，再设置 0 | 自动上报正常，可关闭 |
| 正常负载 | 命令与上报并行 | 周期 min/max 均 10 tick，调度、收发错误及队列溢出计数均 0 |
| 队列溢出恢复 | 一次连续发送 80 条 `status`，不等待回复 | 记录 283 个队列丢弃字节，换行重新对齐后 `ping/status` 正常；硬件收发错误为 0，周期仍为 10 tick |
| 复位默认值 | 每次设置上报周期 60000，再复位，共 3 次 | 每次启动提示正常，`report_ms` 恢复 0，串口各错误计数清零 |

正常验收的结束快照：`samples=9434`，`hal_ms=rtos_tick=94340`，`interval=min=max=10`，`delay_errors=rx_overflow=rx_errors=tx_errors=0`；基础任务剩余栈 828 字节，调试任务剩余栈 1560 字节。额外队列压力测试中调试任务最低观察值为 1476 字节，基础任务仍为 828 字节。队列溢出是主动施加超出请求/响应用法的负载，不代表普通调参发生丢包。

## 执行器与最终状态

SWD 检查 GPIOB/GPIOD/GPIOE 的相关方向与 PWM 输出位为 0，GPIOE 输入回读为 0；`RCC_APB2ENR=0x00040000`，TIM1/TIM15 时钟未开启；`CFSR=HFSR=0`。检查结束后恢复 CPU 运行，保持 UART5 调试固件，自动上报关闭。

阶段 2 的车轮正反转、停车及编码器反馈仍待实施和验收；此次结果不代表车轮或整车运行通过。
