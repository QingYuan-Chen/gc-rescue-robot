# TB67H450 安全基础版源码清理

日期：2026-10-22。源码基于 `81af515ca904fd1c705d21c3eaa0592fa4a57d47` 及清理前已有未提交内容，当前变更未提交。

用户要求更换为 TB67H450，左轮 M4、右轮 M3，删除旧 PID，从新硬件基础层重新开始；最新要求为先不烧录，只清理控制驱动程序。

## 清理范围

- 移除 `App/bsp/motor.*`、`encoder.*`、`wheel_types.h`、旧 `board_startup.*`、`App/control/`、车轮配置、车轮命令与状态格式化模块。
- 移除旧车轮控制测试和 `firmware/stm32/gc_rescue/` 原工程参考业务源码，避免继续依赖旧电机、PID 或机构控制调用链；原始内容包含在清理前快照与 Git 历史中。同级原工程备份不改动。
- 清理生成层的旧电机/编码器定时器文件和 DMA 文件，仅保留 UART5 的串口初始化；CMake、`main.h`、`rescue.ioc` 与当前入口同步收敛。
- 新增 `board_outputs` 低电平保持模块：在 `main()` 第一个用户入口及故障入口配置全部四路驱动 IN1/IN2 和舵机信号为低电平输出。先清锁存，再切换模式，不依赖定时器句柄或 RTOS。
- M3/M4 编码器引脚仅配置普通输入，不采样。运行任务只做 10 ms 周期统计；没有 PID、运动命令或自动输出请求。
- UART5 只保留查询及报告周期设置；板级检查脚本改用 `OK safety` 状态，本轮只检查语法，未连接串口。
- 当前 README、协作约定、工程规范、硬件基线和重构路线同步更新。旧 PID/控制方案文档标为历史资料，不再作为现行实现要求。

工具：STM32CubeCLT 1.20.0，CMake 3.28.1，ARM GCC 13.3.1；主机测试使用 MinGW GCC 15.2.0。

| 主机 CTest | 1/1 通过，覆盖下述四组行为 |

主机验证直接编译正式 `board_outputs.c`、`debug_console.c` 和实际 `main.h`，仅替换 HAL/RTOS/串口：

1. 核对 M4 的 PB6/PB7、PC6/PC7 与 M3 的 PB4/PB5、PD12/PD13 标签。
2. 模拟输出锁存初始全高、GPIO 为复用模式，验证切换输出前清低且不改动无关引脚。
3. 逐一注入 12 个驱动/舵机信号的锁存高电平和模式错误，状态检查能够识别；重新保持后恢复正常。
4. 基础查询正常，五种旧运动/PID/VOFA 命令全部返回未知命令，命令解析期间没有新增 GPIO 写入。
