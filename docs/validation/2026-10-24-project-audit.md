## 待修问题

### A01 / P1：停车逐脚切换输入，可能短暂产生反向组合

- 位置：[motor.c](../../firmware/stm32/App/bsp/motor.c) 的 `configure_pins()`、`stop_side()`；[board_outputs.c](../../firmware/stm32/App/bsp/board_outputs.c) 的 `hold_low()`。
- 根因：先写低 ODR，再调用 `HAL_GPIO_Init()` 将两个输入从 AF 改为 GPIO。AF 模式下 ODR 不控制引脚，而本工程 HAL 的 [stm32h7xx_hal_gpio.c](../../firmware/stm32/Drivers/STM32H7xx_HAL_Driver/Src/stm32h7xx_hal_gpio.c) 第 241 行位于逐引脚循环内，每次只改一个引脚的 MODER；不是一次切换两个输入。
- 触发：M4 的 PB6/PB7、M3 的 PB4/PB5 均按 IN1 在前的顺序处理。正向驱动时 IN1 恒高，IN2 在高低之间 PWM；若停车落在 IN2 为高的制动段，先把 IN1 切低而 IN2 仍为 AF 高，会短暂形成 `IN1=0, IN2=1`，与原请求方向相反。运行中故障关闭也经过相同逐脚逻辑。
- 证据边界：这是根据已读 HAL 执行顺序和当前 PWM 组合推导出的输入瞬态，未测量脉宽、驱动芯片实际响应或机械位移。不能据此断言电机已发生可见反转，但原注释“不能泄漏反向脉冲”没有依据，现已纠正。
- 测试缺口：当时的 `test_wheel_io.c`（已清理，见 Git 历史）GPIO 替身虽逐脚改 MODER，但只在调用前后检查约束，没有观察每次 MODER 写入后的引脚组合，因此测试通过不能排除此问题。
- 建议：将一对输入的切低作为 BSP 内的一次完整操作。预置双低锁存后，以同一次 MODER 写入接管同端口的两个输入，再停止 PWM；正常停车与故障关闭使用一致的底层时序。测试应观察逐次寄存器写入中的组合，并在授权上板后测量实际波形。本轮未实施该行为修复。

### A02 / P2：定时器安全初始化位于 CubeMX 保留区之外

- 位置：[Core/Src/tim.c](../../firmware/stm32/Core/Src/tim.c)，尤其 `pwm_init()` 和 `HAL_TIM_PWM_MspInit()`；HAL 时基文件也包含手写配置逻辑。
- 根因：`tim.c` 是完整手写文件，没有 `USER CODE` 保留区，和规范“手写接入放在保留区或独立模块”的要求不一致。当前延迟 GPIO AF 接管依赖这份手写实现，而不是 `.ioc` 能完整描述的行为。
- 证据：上一轮隔离生成的 `build/tb67h450-basic-20261023/cubemx/rescue/Core/Src/tim.c` 在第 88、236、294 行调用 `HAL_TIM_MspPostInit()`，初始化过程中就把对应电机引脚切到 AF；正式源码刻意不调用。生成器还能用独立数值替换集中配置宏，造成后续配置漂移。
- 影响：直接重新生成会覆盖自有逻辑，使“命令到来前始终由 GPIO 持低”的约束不再由当前实现保证。`main()` 初始化后的再次关闭仍存在，但不能代替整个初始化过程的约束。此问题不等于当前启动一定转轮。
- 建议：把不能由 `.ioc` 表达的初始化和引脚接管职责放入生成器不会覆盖的 BSP 模块，以保留区接入；隔离重生成后核对入口、GPIO 时序并重新编译。另需解决上轮已记录的生成器 Windows 路径重复拼接错误。本轮只补充风险说明，未重构初始化归属。

## 中文注释补充范围

- `motor`：左右索引、AF1 复用、占空比单位和 CCR 边界、预装载提交、部分启动失败清理、逐周期状态迁移及停车瞬态限制。
- `encoder`：启动清零、运行不清 CNT、双轮独立读取、模差分、64 位累计、实际单位与未校准方向。
- `wheel_io`：请求/快照的生产者和消费者、临界区用途、停止优先依赖的任务顺序、请求有效期、故障锁定及软件检查边界。
- 调试与运行入口：完整快照、严格整数解析、单轮命令隔离、丢字节后整行丢弃、TX 缓冲区生命周期、绝对周期调度。
- 定时器与 GPIO：资源冲突原因、CH1N 单独启用、编码器 TI12 极性、TIM6 时钟与初始化标志清理、GPIO 状态检查为何同时看 ODR/MODER。

新增注释解释“为什么、由谁调用、单位与限制”，没有对每条赋值重复翻译。保留第三方许可证、生成器固定说明与原文件编码/换行。
