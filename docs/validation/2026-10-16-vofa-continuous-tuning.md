# VOFA 持续闭环与滑块命令验证

日期：2026-10-16。基线：`develop` 的 `12990cab273032e0f19724e97089a4f1d649423f`，在上一批未提交的 VOFA 接口变更上继续修改。以下为本轮接口实现时的离线快照，当时没有连接串口、烧录、驱动车轮或整定参数。后续用户要求修复烧录，已完成[Debug 烧录恢复与停车查询](2026-10-16-vofa-flash.md)；用户随后授权提交并推送当前调试程序，提交前复核见本文末节，原离线结果保留。

## 需求与实现

用户要求调试时取消 2000 ms 到期停车，将目标速度改为独立参数输入；随后提供滑块实际命令 `pid edit left kp:542`，要求固件同步适配。

- `wheel target left:<值>` 只设置目标参数：停车和开环时不启动；已闭环时下一周期采用，不清积分，也不启用未选轮。右轮与双轮接口同样拆分。
- `wheel start left` 按已保存目标启动持续闭环，无运行期限，不需要发送续期命令；旧 `wheel speed ... <ms>` 命令及控制接口已移除。
- `wheel stop` 优先停车并清 PI，保留目标参数供下一次显式开始。上电目标为零、默认停车；复位恢复零目标和零增益。
- 开环接线检查仍限定 10～2000 ms；限时检查只作用于开环，没有使用极大时长或隐藏续期来实现持续闭环。
- `pid edit left kp:542` 直接编辑 Kp=542.000 草稿，仍需 `pid apply left` 才生效；Ki/Kd 和目标参数同步支持冒号或空格分隔。Kd 继续只接受零，数值最多三位小数，命令末尾仍需实际 CR/LF。
- 输入冒号不改变输出协议：只有 FireWater 采样使用 `vofa:`，普通回执继续不带冒号，不回显输入以免产生伪通道。
- 状态增加 `setpoint_left_milli/setpoint_right_milli`，表示已保存目标；原 `target_*_milli` 和 VOFA 通道 1 继续表示当前实际控制目标，停车时为零。`remaining_ms` 只表示开环期限，持续闭环为零。

目标范围 ±10 counts/10 ms、闭环输出 ±250‰、换向间隔、停止优先及周期故障锁定规则保留。关闭波形、停止发命令或断开串口均不会终止持续闭环，结束调试须主动停车。参数默认值和接线未修改，不替用户选择增益；542 只作为用户所给命令的解析用例。

接口操作见 [VOFA 左轮调参](../VOFA左轮调参.md)，模式与后续比赛约定见 [底盘控制规则](../底盘控制规则与比赛动作.md)。

- `wheel_control_contract`：21 组场景、14211 项检查。包含独立目标参数、停车时编辑不启动、控制周期边界生效、运行中保留积分、目标编辑不启用另一轮、持续超过 2 秒及 tick 回绕、停止与更新并发、恢复显式开始、开环限时保持、周期故障拒绝、冒号/空格解析及非法值拒绝。实际 `kp:542` 在应用前不改活动参数，应用后正确回读，右轮参数保持不变。
- `pi_contract`：4 组场景、4033 项检查，显式积分、抗饱和和换向回算算法保持原规则。
- `vofa_console_contract`：8430 项检查，模拟运行 3300 ms，产生 238 帧波形。使用实际滑块格式编辑增益、设置目标并显式开始；超过 2 秒仍闭环，2400 ms 关闭采集后继续输出。2700 ms 可读的停车命令在 2710 ms 控制周期采用；停车后再输入目标仍保持零输出。该时间仅是确定性主机模拟，不能作为无线或实车停止时延。

测试代码全部留在 `tests/wheel_control/`，不进入固件。主机结果位于 `build/vofa/host-og/Testing/Temporary/LastTest.log` 与 `build/vofa/host-ofast/Testing/Temporary/LastTest.log`。复测使用对应主机构建目录的 `cmake --build` 和 `ctest --output-on-failure -V`；ARM 按共享 CMake 预设配置并构建。
