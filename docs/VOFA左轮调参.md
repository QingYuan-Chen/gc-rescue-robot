# VOFA+ 左轮调参

日期：2026-10-16。状态：接口实现及离线验证完成；Debug 已完成[烧录、回读和 UART5 停车查询](validation/2026-10-16-vofa-flash.md)，`wheel target left:0.1` 已实机确认保存且不启动电机。VOFA+ GUI、连续波形和真实闭环仍待用户联调，尚未整定。最新变更为独立目标输入、持续闭环和滑块冒号命令，见 [连续调参与滑块验证](validation/2026-10-16-vofa-continuous-tuning.md)；初版记录见 [VOFA 接口验证](validation/2026-10-15-vofa-interface.md)。

UART5 经无线 DAPLink 连接电脑，调参固定使用 **C 左轮**，由用户操作。当前控制器为 PI，Kp、Ki 上电默认均为零，Kd 未启用；原 CCR 参数不能直接填入当前接口。增益仅保存在 RAM，复位恢复 [默认配置](../firmware/stm32/App/config/wheel_pid_config.h)，不自动写 Flash 或复制到右轮。

测速改进方案见[车轮速度测量设计](车轮速度测量设计.md)，当前待审核实施。计划保持八通道顺序，将速度和误差改为与 PI 共用的 50 ms 窗口估计；当前固件和下述协议示例仍使用每 10 ms 的原始整数增量，不能据显示三位小数推定测速已升级。

## 1. 连接与界面

- 串口：115200、8N1、无流控，PB13 TX、PB12 RX；按当前设备选择 COM 口，历史 COM5 不作为固定编号。
- VOFA+ 接收协议选择 **FireWater**；发送选择字符串模式，命令末尾发送实际 LF（字节 `0A`），也支持 CR/CRLF。
- 固件上电关闭连续采集。发送 `vofa on` 开始，控制任务每 10 ms 采样，目标上报频率 100 Hz。
- 波形一绑定目标速度、实际速度、速度误差；波形二绑定最终输出。Kp、Ki、Kd 分别绑定数值显示，命名为“实际 Kp”“实际 Ki”“实际 Kd（未启用）”。输入框独立显示待编辑值。
- 普通时间轴设置 Δt=10 ms。若要保留缺样时的真实时间间隔，将通道 0 作为 X 轴；不要用电脑接收时间代替 MCU 采样时刻。

依据：[FireWater 格式](https://www.vofa.plus/docs/learning/dataengines/firewater)、[命令参数与控件绑定](https://www.vofa.plus/docs/learning/start/data_cmd_parameter)、[波形时间轴](https://www.vofa.plus/docs/learning/widgets/wave)。软件界面控件名称可能因安装版本不同而变化，本次没有修改电脑端 VOFA 配置。

## 2. 固定八通道

每帧固定顺序，不混入可变通道或临时诊断项：

| 通道 | 内容 | 单位与含义 |
| --- | --- | --- |
| 0 | 时间戳 | 相对 `vofa on` 的秒数，三位小数，取自 MCU 控制采样时刻 |
| 1 | 目标速度 | counts/10 ms，三位小数 |
| 2 | 实际速度 | 编码器每 10 ms 有符号增量，前进为正 |
| 3 | 速度误差 | 目标减反馈，counts/10 ms，三位小数 |
| 4 | 最终输出 | 有符号占空比千分比，已包含限幅、取整和换向间隔 |
| 5 | Kp 回读 | 该周期实际使用的 Kp，三位小数 |
| 6 | Ki 回读 | 该周期实际使用的 Ki，三位小数 |
| 7 | Kd 回读 | 固定 `0.000`，微分未实现，非零设置会拒绝 |

数据格式为 `vofa:t_s,target,measured,error,duty,kp,ki,kd`，末尾 CRLF。例如：

```text
vofa:0.010,1.250,1,0.250,20,80.000,400.000,0.000
```

上例仅用于解释格式，数值来自离线输入，不是推荐电机参数。全部通道取自同一控制周期快照。停车、开环或模式过渡期间，目标取控制层当前速度目标（通常为 0），误差仍按目标减反馈计算；此时误差不代表 PI 正在纠偏，运行模式由 `wheel status` 查询。

P、I 分项、未限幅输出、模式、故障、限幅和换向继续由 `wheel status` 查询，不占固定通道。参数和状态回执为独立普通文本行，全部经同一调试任务串行发送，不插入波形行中间。

普通 `OK`、`ERR`、`READY` 行不含冒号，避免被当作采样数据。这是针对 [官方 FireWater 解析器](https://github.com/je00/Vodka/blob/master/dataengines/firewater/firewater.cpp)的格式约束：其冒号分支未检查数值转换成功，帮助或错误消息中的冒号也可能生成伪采样；不带冒号且以文字开头的行才按普通文本处理。

## 3. 编辑、应用与回读

| 命令 | 行为 |
| --- | --- |
| `pid edit left kp:<值>` | 编辑左轮 Kp 草稿，如滑块发送 `pid edit left kp:542` 表示 542.000，不另做比例换算 |
| `pid edit left ki:<值>` | 编辑左轮 Ki 草稿 |
| `pid edit left kd:0` | 接受零值，继续明确为 PI；非零回复 `kd_unsupported` |
| `pid apply left` | 提交整组草稿，等待周期任务处理 |
| `pid get left` | 查询当前生效值及是否仍等待应用回执 |
| `vofa on` / `vofa off` | 开始／结束采集，不启动或停止电机 |
| `vofa status` | 查询采集开关、积压和丢样统计 |
| `wheel target left:<值>` | 设置左轮目标参数；停车时不启动，闭环中下一周期采用且保留积分 |
| `wheel start left` | 按已保存目标启动左轮持续闭环，右轮停用，无到期停车 |
| `wheel stop` | 停车并清控制状态，保留目标参数供下一次显式启动 |
| `wheel status` | 查询已保存目标、当前实际目标、模式及输出 |

数值参数支持冒号或空格分隔，例如 `pid edit left kp:542` 与 `pid edit left kp 542` 等价。Kp、Ki 输入范围为 `0..10000.000`，最多三位小数，最小输入步长 `0.001`。这是协议数值边界，不是建议整定范围。拒绝负值、指数、NaN/Inf、缺整数位和超出精度的输入，不静默截断。Kp 单位为 ‰/(counts/10 ms)，Ki 单位为 ‰/[(counts/10 ms)·s]；Ki 由算法显式乘 0.01 s。

草稿首次从当前参数初始化。每次编辑回传整组草稿，未修改项保留；错误输入不改变草稿或活动参数。命令采用“发送一条，等待回复”，单行最多 95 字节。

VOFA 参数控件绑定的命令模板使用 `pid edit left kp:%.3f` 和 `pid edit left ki:%.3f`，末尾添加实际换行。只输出整数的滑块可使用 `%d`，如用户实际发送的 `pid edit left kp:542`；需要小数时使用 `%.3f`，避免默认 `%f` 生成六位小数而超出协议精度。应用按钮只发送 `pid apply left`，查询按钮发送 `pid get left`。Kp/Ki 滑块只编辑草稿，仍须点击应用并等待生效回执。

目标速度使用独立数值控件，命令模板为 `wheel target left:%.3f`，输入范围 `-10..10`，步长 `0.001`，单位为 counts/10 ms；不用整数滑块代替需要小数的低速输入。“开始”按钮发送 `wheel start left`，“停车”按钮发送 `wheel stop`。每条命令末尾带实际 LF/CRLF；按钮单次发送，避免按下与松开双触发或循环发送。目标更新不需要 `pid apply left`：已启动时下一控制周期直接采用；未启动时只保存参数。

操作顺序为：设置增益并应用 → 输入目标 → 点击开始 → 观察波形并按需调整目标/增益 → 点击停车。通道 1 始终显示当前控制目标，停车和未启用时为 0；输入框中的已保存目标可由 `wheel status` 的 `setpoint_left_milli` 核对，例如 `2000` 表示 2 counts/10 ms。普通停车保留已保存目标，重新开始时使用该目标；复位后目标和增益均恢复默认零值。

一次应用有两个阶段：

```text
OK pid left queued id=1
OK pid left applied id=1 tick_ms=12340 kp=... ki=... kd=0.000 d_enabled=0
```

`queued` 仅表示整组请求已入队。`applied` 表示车轮任务已在 `tick_ms` 所指周期入口采用；八通道中的参数从对应采样时刻起改变。缓冲中的较早波形仍按原采样顺序发出，不把它们的参数改成新值。等待结果期间重复编辑或应用回复 `busy`，不会覆盖前一个请求；查询仍可用。

周期异常与改参请求同周期出现时，锁定停车并拒绝这次参数更新，回复 `ERR pid left rejected ... period_fault_reset_required`，原参数保持有效。停止或开环到期与更新同时出现时，可以采用参数，但输出和 PI 状态按停止规则清零；增益或目标参数更新不能启动动作。

运行中修改 Kp 立即影响后续比例项。修改 Ki 保留已有积分输出，新 Ki 影响后续积分累加；Ki 改为零时清积分并关闭回算，进入纯 P。回算增益保持配置值 `10/s`，不纳入当前调参命令。固件没有无扰增益切换，改 Kp 或关闭积分可能引起输出变化，波形用于观察实际结果。

闭环调参无运行时长和到期停车，启动后保持运行，直到显式停车、切换模式或触发已有周期故障；不需要重复发送命令续期。速度目标仍为 ±10 counts/10 ms，闭环输出 ±250‰，停止优先、换向间隔及周期故障锁定停车规则保留。**关闭波形、断开 VOFA 或停止发送命令均不会使持续闭环自动停车，结束调试须发送 `wheel stop`。** 目标速度零仍是闭环给定，不等同于退出闭环。启动左轮及具体参数由用户决定。

旧 `wheel speed ... <ms>` 命令已删除，独立目标设置与显式启动接管其职责；右轮和双轮同样通过 `wheel target right/both ...`、`wheel start right/both` 使用，当前调参仍固定左轮。开环接线检查沿用 `wheel left/right/both ... <ms>`，仅这类请求保留 10～2000 ms、10 ms 步长的时限，不作为闭环调参期限或比赛动作时限。

## 4. 采样、带宽与诊断

控制任务只复制快照到 32 帧环形缓冲，格式化和发送在低优先级调试任务执行。缓冲满时丢弃最旧样本、保留近期样本，并累计 `dropped`，不会阻塞控制；普通积压仍按时间顺序发送，不重放控制动作。

8 通道最大宽度数据行离线验证为 74 字节，100 Hz 时为 7400 字节/秒，约占 115200/8N1 理论线速的 64.2%。这不含命令回执和状态查询，也不证明无线链路可以持续零丢样。调试循环先批量处理接收，再发送一帧；有积压时不等待接收，空闲采集时最多等待 1 ms。

`vofa on` 自动关闭原 `report_ms` 周期长文本；采集中设置非零 `report_ms` 会拒绝，手动状态查询仍可用。频繁长查询可能导致积压或丢样，主要观察固定八通道即可。

`vofa status` 字段：

| 字段 | 含义 |
| --- | --- |
| `enabled` / `queued` | 开关与当前缓冲样本数 |
| `captured` | 本次采集产生的样本数 |
| `dropped` | 本地缓冲满或格式化失败而丢弃的样本数 |
| `sent` | UART 发送成功的波形帧数，不能等同于电脑已收到 |
| `tx_errors` | 波形发送失败次数；底层总串口计数另见 `status` |

`vofa off` 清空未发缓冲、保留诊断计数；下次从关闭状态 `vofa on` 时清计数并重设时间零点。已开启时重复 `vofa on` 不重置时间或计数。无线链路中丢包不一定反映在 MCU 的计数中，应同时检查接收端时间戳间隔。当前未加入自定义 CRC、重传或第二套波形协议。

## 5. 实现与验收

- `control/wheel_drive`：参数请求交接、周期入口整组采用及结果快照，唯一运动编排入口。
- `control/wheel_pid`：参数更新与积分生命周期，纯控制逻辑。
- `debug/pid_commands`：参数语法、草稿和应用结果回执，不直接修改控制器内部变量。
- `debug/vofa_stream`：有界采样缓存、八通道格式与统计，不读写串口或电机。
- `debug/debug_console`：统一命令接收、响应及波形发送调度，复用现有 `bsp/debug_uart`。
- `robot_app`：在每次车轮周期完成后调用采样入口，控制层不反向依赖 VOFA。

离线测试直接编译正式控制、调参、采样和控制台模块，覆盖参数有效时刻、整组更新、运行期限、积分保留/清零、右轮隔离、拒绝输入、同帧一致性、时间回绕、缓冲溢出和串口收发调度。测试代码只在 `tests/wheel_control/`，不进入固件。

已通过连接、零增益回读、停车、目标输入及 10 ms 周期快照检查；目标验证后已恢复零值。后续先核对 VOFA+ 实际控件字节、八通道连续波形和参数 applied 回执，再由用户操作左轮观察运动。纯查询只需核心板供电；运动验收需要电机供电并确认车轮架空。完整硬件时序、采集负载下的任务栈余量、无线吞吐和真实闭环性能仍待实测。
