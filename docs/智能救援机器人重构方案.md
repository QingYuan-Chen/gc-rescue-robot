# 智能救援机器人重构方案

版本：V2.0。日期：2026-10-22。TB67H450 新硬件从基础层重新开始。

## 当前边界

左轮 M4，右轮 M3；驱动和编码器信号以 [硬件基线](TB67H450硬件基线.md) 为准。旧接线、方向符号和 PID 不继承。旧控制实现及参考业务代码已退出源码树，历史验证记录仅用于追溯。

本轮只清理并建立安全基础版，不烧录、不转轮。保留经过独立构建检查的 MCU 启动、时钟、HAL 时基、FreeRTOS、UART5 和运行观测能力，不重做与硬件更换无关的基础工具。

## 实施顺序

| 阶段 | 实现与验收 |
| --- | --- |
| 0 安全基础 | 驱动输入固定低电平，移除旧 PWM、控制器和运动入口；构建和主机检查后，经授权烧录并测量上电/复位状态 |
| 1 新驱动 | 按 TB67H450 真值表设计单轮限时开环、停止和故障入口；先 M4，再 M3，逐路确认实际轮子和正反方向 |
| 2 编码器 | 接入 M4 的 PC6/PC7 与 M3 的 PD12/PD13；手动转轮确认独立反馈、方向、每圈计数和采样周期 |
| 3 速度控制 | 根据已验证的反馈单位、输出方式和任务周期重新设计控制器；不移植旧 PID 参数 |
| 4 组合运动 | 基于已验收的轮速能力设计差速、转向、换向和停稳判据 |
| 5 外设 | 云台、夹爪、IMU 和视觉通信逐模块接入 |
| 6 赛题协同 | 根据规则、场地和真实硬件能力设计任务状态机及动作流程 |

每阶段只实现当前需要的功能。源码可构建、Flash 写入一致、真实运行通过是不同结论；尚未烧录的版本不能更新为板上当前版本。新的阈值、方向和参数以本阶段实测为依据。

## 当前产物

- 输出保持：`App/bsp/board_outputs.c`，在 `main()` 入口和故障入口使用相同低电平策略。
- 基础运行：`App/robot_app.c` 与 `App/runtime/`，不包含控制任务。
- 调试：UART5 仅保留查询与自动报告周期设置。
- 验证：[主机测试](../tests/safe_baseline/README.md)及[本轮清理记录](validation/2026-10-22-safe-baseline-cleanup.md)。
